## 1. 霜藤束缚（overlay，缠身态）

- 推荐文件名：`binding-vines-v2.svg`（保留 `binding-vines.svg` 供对照，不直接覆盖）。
- 规格建议：viewBox `0 0 300 400`，与现版一致，随 `.hero` 高度缩放；主藤描边 9px，细霜描边 2px。
- 叠层位置：覆盖 `shen-yan-bound-v2.png` 的小腿与腰侧两层缠绕；上缘不高于腰带玉饰，下缘止于靴底基线，不遮面部、围巾结与手中物。
- 矢量设计方案：
  - 两组同心缠绕：腿部组（自画面左下 `~(75,390)` 起两圈盘绕上升）、腰侧组（右侧 `(230,388)` 起单圈斜上收梢于 `(94,177)` 附近），延续现版路径骨架。
  - 主藤 `#273e32`（墨青），端梢用短断笔（`stroke-dasharray` 模拟飞白），避免漂浮粗圈。
  - 霜层 `#889889`（灰青）细线沿主藤上缘偏移 3px 重复路径，透明度 0.8；节疤处 3–5 枚三瓣小叶用 `#667c51`（草绿）填充，仅点缀不铺满。
  - 新增「呼吸感」由 CSS 动画作用于整层（±0.5% scale），不改 SVG 内部。
- 验收：与受困立绘叠合后，藤梢起止点均落在肢体轮廓内侧；250px 高度下藤不糊成黑块。

## 2. 断藤（燃烧断裂瞬时反馈）

- 推荐文件名：`severed-vines.svg`（矢量两段）+ 可选位图帧 `severed-vines-embers.png`（2x 透明 PNG）。
- 规格建议：viewBox `0 0 300 400` 同束缚层，断口位置预置两处：小腿段 `(约110,310)`、腰侧段 `(约180,240)`，与火卡命中反馈帧对齐。
- 矢量设计方案：
  - 三条断裂藤段，每段为原缠绕路径的局部裁形，断口一侧收尖（`stroke-linecap="round"` + 短渐隐 dash），呈向外弹出的微弯弧度。
  - 断口炭化：断头 6–10px 涂朱砂 `#98483c` 渐晕（SVG `<linearGradient>` 由朱砂至透明），延续火系「炭墨根部、赭红焰身」语言；禁止橙黄高亮。
  - 余势用 2–3 根 1.5px 灰青短线表示藤液冷烟，位置不压人物躯干中心。
- 位图备选提示词（仅当矢量表现不足时）：

  > Production transparent PNG game VFX overlay sprite. Chinese ink wash style. Three severed frost vine segments recoiling outward, dark ink-green (#273e32) broken ends tapered with dry-brush feibai gaps, each cut edge smoldering with restrained cinnabar-red (#98483c) to charcoal gradient embers, two thin pale grey-teal smoke dashes rising. NO flames, NO sparks particles, NO glow. Segments arranged along a human shin-to-waist arc but WITHOUT any character drawn. Generous transparent margins. No text, no frame, no background. Genuine transparent background.

- 叠层位置：出现在解缚反馈的 1.1 秒窗口内（现版 `breaking` class 时长），先于立绘切换半拍。
- 验收：断藤不与完整缠绕层同帧共存；炭化色不出现在藤身中段。

## 3. 残碑（场景前景物件）

- 推荐文件名：`broken-stele.svg`；若入背景分层则导 `broken-stele-{far,mid}.png`。
- 规格建议：viewBox `0 0 220 360`，纵向碑体；放置于战场右侧偏后、敌人站位之后景深处，高度约为敌人立绘 1.2 倍（建议值，非当前实现要求）。
- 矢量设计方案：
  - 碑体轮廓：上端斜向缺口的不规则五边形，边缘 2–3 处剥落凹口；填充灰青 `#597b79` 至旧纸 `#d7cdb9` 的纵向淡渐变，模拟风化受光面。
  - 碑纹：三列抽象残纹——短横划痕、回折云雷势、缺笔方框，全部为非文字几何形（参考钟鼎残纹意象，标注：具体纹样出处待核验，仅作装饰）；描边墨青 `#293b32`，透明度 0.35–0.5，集中在碑面左半，右半留给藤影叠压。
  - 藤蚀：两条 7px 墨青藤自碑缝穿出环绕下部，与 A04 残碑藤妖待机图的藤甲路径语言一致，但独立成层，便于拆合。
  - 根部：淡灰薄霜苔线接地，接地方式与人物脚底基线相同。
- 验收：缩略至 120px 高仍可读出「断碑」剪影；碑面无任何可辨汉字或拉丁字符。

## 4. 碎碑（碑块碎片，战斗余韵/拓展储备）

- 推荐文件名：`stele-debris.svg`（组合件）+ 单体 `stele-shard-{1..3}.svg`。
- 规格建议：单体碎片 viewBox `0 0 80 80` 内自含；组合层 viewBox `0 0 300 200`，贴地散落。
- 矢量设计方案：
  - 三块异形碎片取自残碑轮廓的局部：碑肩块（带缺口边）、碑面纹块（保留一小片抽象残纹，透明度同残碑）、碎粒（三两点 6px 以内小屑）。
  - 断面受光：裂面用旧纸 `#d7cdb9` 平涂，轮廓墨青单线；不画裂纹辉光。
  - 布局：沿假想地平线左低右高散落，重心在画面左 1/3，为右侧人物与敌人留出空位。
- 使用场景说明：当前新手关未实现「残碑被击碎」的演出；本件为残碑战胜利余韵与后续剧情（碑毁妖散）储备，标记为拓展建议。
- 验收：碎片与残碑本体颜色、纹样、线宽一致，可拼合回完整碑形示意。

## 统一叠加与工程备注

- 四层叠序建议（自下而上）：场景背景 → 残碑/碎碑（景深后层）→ 敌人/主角立绘 → 霜藤束缚 → 断藤/特效。现版仅「背景 → 立绘 → 束缚层」，碑体与碎片层为拓展建议。
- 所有 SVG 保持无内嵌位图、无外部字体，可被 `server.js` 静态白名单直接服务（`src/assets/` 现状）。
- 实际产出文件先交付 `docs/content/generated/tutorial/pending-review/objects/`，审核后再迁入 `src/assets/`，不覆盖现有资源。
